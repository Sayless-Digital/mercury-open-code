## Summary
Fixed session switching issues and improved the Mercury global command to auto-stop existing sessions.

## 1. Fixed Session Switching Issue

### Problem
When sending a message and quickly switching sessions:
- Messages would disappear from the chat panel
- Session tabs would show empty chats
- Switching back would not restore messages

### Root Causes Identified

**Issue 1: Non-Singleton useOpencode() Composable**
- Each store (SessionStore, ChatStore) created its own instance of `useOpencode()`
- Each instance had its own `sessionId` ref
- When SessionStore switched sessions, ChatStore's `sessionId` didn't update
- Result: `turns` computed filtered by wrong sessionId, showing 0 turns

**Issue 2: Aggressive Message Clearing**
- On session switch, messageMap was cleared completely
- API calls to load messages would race with session switches
- If user switched before API completed, results were discarded
- Result: Empty chat panels after rapid session switching

### Solutions Implemented

**Solution 1: Singleton Pattern for useOpencode()**
- File: `mercury-coder/src/composables/useOpencode.js`
- Created `getSharedState()` function that returns singleton state
- All calls to `useOpencode()` now share the same refs:
  - `sessionId` - shared across all stores
  - `loading`, `error`, `abortController`, etc.
- Removed duplicate local variable declarations that shadowed shared state
- Result: SessionStore and ChatStore now see the same `sessionId` value

**Solution 2: Message Caching Strategy**
- File: `mercury-coder/src/stores/chat.js`
- Changed approach: Keep ALL messages from ALL sessions in messageMap
- Added `loadedSessions` Set to track which sessions have been loaded
- `turns` computed now filters by sessionId to show only relevant messages
- Skip API calls if session is already loaded (prevents duplicates)
- Cache API results even if user switches away (prevents data loss)
- Result: Messages persist when switching between sessions

### Files Modified
1. `mercury-coder/src/composables/useOpencode.js`
   - Implemented singleton pattern for shared state
   - Removed duplicate variable declarations
   - Fixed return statement to use shared refs directly

2. `mercury-coder/src/stores/chat.js`
   - Added `loadedSessions` Set for tracking loaded sessions
   - Removed `messageMap.clear()` calls on session switch
   - Updated watch() callback to cache messages
   - Updated `loadMessagesForSession()` to check cache first
   - Improved logging to distinguish total vs session-specific messages

## 2. Improved Mercury Global Command

### Problem
When running `mercury start` while Mercury was already running:
- Command would show error: "Already running, use mercury stop first"
- User had to manually run `mercury stop` then `mercury start`
- Inconvenient for quick restarts

### Solution
Modified `mercury start` to automatically stop existing sessions before starting a new one.

### Changes Made

**File: `/usr/local/bin/mercury`**
- Modified `start_mercury()` function
- Added auto-detection of running sessions
- Calls `stop_mercury()` automatically if already running
- Shows clear status messages during the process
- Updated help text to reflect new behavior

**Before:**
```bash
if is_running; then
    echo "Already running"
    exit 1
fi
```

**After:**
```bash
if is_running; then
    echo "Already running, stopping first..."
    stop_mercury
    echo "Starting fresh session..."
fi
```

### Files Modified
1. `/usr/local/bin/mercury` - Main command script
2. `/usr/local/bin/mercury.backup` - Backup of original
3. `GLOBAL_COMMANDS.md` - Updated documentation

2. No limit on cache size (could grow large with many sessions)
3. Event stream might receive duplicate events during rapid switching
